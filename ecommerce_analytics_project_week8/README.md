# E-Commerce Order Analytics System

An end-to-end data analytics pipeline built with **Python** and **SQL (SQLite)**
that generates, cleans, analyzes, and reports on messy e-commerce order data.

## Project Structure

```
ecommerce_analytics_project/
├── data_generation.py          # Part 1: generates 4 raw CSVs with intentional data issues
├── data_cleaning.py             # Part 2: cleaning functions + data quality report
├── load_database.py             # Loads cleaned CSVs into SQLite
├── cli_report.py                 # Part 4: command-line reporting tool
├── test_edge_cases.py           # Part 5: edge case tests
├── sql/
│   └── analysis_queries.sql     # Part 3: all 16 SQL queries (basic → advanced)
├── data/
│   ├── raw/                     # Generated messy CSVs
│   │   ├── customers.csv
│   │   ├── products.csv
│   │   ├── orders.csv
│   │   └── order_items.csv
│   └── cleaned/                 # Cleaned versions of the same 4 files
├── database/
│   └── ecommerce.db             # SQLite database (loaded from cleaned data)
└── reports/
    └── data_quality_report.txt  # Auto-generated report of every issue found
```

## Setup

Requires Python 3.10+ and `pandas`:

```bash
pip install pandas
```

## Pipeline: How to Run Everything (in order)

```bash
# 1. Generate the 4 raw CSVs (~500+ rows each, with intentional issues)
python3 data_generation.py

# 2. Clean the data -> writes cleaned CSVs + reports/data_quality_report.txt
python3 data_cleaning.py

# 3. Load cleaned CSVs into a SQLite database
python3 load_database.py

# 4. Explore the SQL analysis queries directly, e.g.:
sqlite3 database/ecommerce.db < sql/analysis_queries.sql

# 5. Run the CLI reporting tool
python3 cli_report.py --type monthly --start 2024-06-01 --end 2024-06-30
# ...or run it interactively (no flags) and answer the prompts:
python3 cli_report.py

# 6. Run the edge case tests
python3 test_edge_cases.py
# (or, if pytest is installed): python3 -m pytest test_edge_cases.py -v
```

The database and all CSVs included in this zip were already generated by
running the above sequence, so you can inspect `database/ecommerce.db` and
the `data/` folder immediately — or delete them and regenerate from scratch
using the commands above.

## Part-by-Part Notes

### Part 1 — Data Generation (`data_generation.py`)
- Generates `customers.csv`, `products.csv`, `orders.csv`, `order_items.csv`,
  each with 500+ rows (this run produced 600 / 140 / 2,500 / 4,802 rows).
- Intentional issues seeded: 5% NULL `customer_id`, 3% negative `quantity`
  (returns), ~6% of orders with `DD-MM-YYYY` dates, messy product name
  casing/spacing, 2% invalid emails.
- **Referential integrity guarantee:** `order_items.csv` is generated by
  iterating over the *already-created* `orders` list and reusing their
  `order_id`s — it never invents a new order_id — so every `order_id` in
  `order_items.csv` is guaranteed to exist in `orders.csv` by construction.
  `check_referential_integrity()` in the cleaning step re-verifies this.

### Part 2 — Data Cleaning (`data_cleaning.py`)
Implements exactly the four required functions:
- `clean_orders(df)` — normalizes both date formats to
  `YYYY-MM-DD HH:MM:SS`; normalizes missing/`"NULL"`/blank `customer_id` to
  a consistent NA marker (rather than silently dropping rows).
- `clean_products(df)` — collapses extra whitespace and applies title case
  to `product_name`.
- `validate_emails(df)` — returns the list of `customer_id`s with malformed
  emails (regex-based check for `@` and a domain).
- `check_referential_integrity(order_items_df, orders_df)` — returns the
  subset of `order_items` rows whose `order_id` doesn't exist in `orders`.

Running it prints and saves a full data-quality report to
`reports/data_quality_report.txt`.

### Part 3 — SQL Analysis (`sql/analysis_queries.sql`)
All 16 required queries, verified to execute successfully against the
loaded database:
1. Total revenue per category
2. Top 10 customers by order value
3. Month-wise order count (last 12 months)
4. Customers with no delivered items
5. Products with more returns than purchases
6. Return rate per category
7. Running total of revenue per region (window function)
8. `DENSE_RANK` of products by revenue per category
9. `LAG` for days-between-orders + "At Risk" flag
10. Multi-level CTE: monthly revenue → category → count
11. `NTILE(4)` customer quartile segmentation
12. Year-over-year monthly revenue comparison
13. `FIRST_VALUE` / `LAST_VALUE` category-shift analysis
14. Cumulative revenue distribution (Pareto-style)
15. Cohort retention analysis by registration month
16. Self-join for "frequently bought together" product pairs

### Part 4 — CLI Tool (`cli_report.py`)
Pure standard library (`sqlite3`, `argparse`, `datetime` only — no pandas).
Supports both:
- **Non-interactive:** `python3 cli_report.py --type monthly --start YYYY-MM-DD --end YYYY-MM-DD`
- **Interactive:** run with no arguments and follow the prompts (report
  type → date range, with an option to auto-pick the latest available range).

Outputs total orders, revenue, unique customers, top 3 products, and a
percent-change comparison against the immediately preceding period of equal
length.

### Part 5 — Edge Case Tests (`test_edge_cases.py`)
Five tests (four required + one bonus SQL-level check), each documenting
the expected system behavior:
1. `order_items` referencing a non-existent `order_id` → detected by
   `check_referential_integrity()`, and naturally excluded from revenue via
   `INNER JOIN` in SQL.
2. `discount_percent > 100` → flagged as invalid, and revenue calculation
   clamps the discount to `[0, 100]` so revenue never goes negative.
3. `quantity == 0` → computes cleanly to zero revenue (no crash) and is
   flagged separately for review as likely bad data entry.
4. `order_date` in the future → detected via comparison against
   `datetime.now()`, flagged as excludable from trend reports.
5. (Bonus) Confirms the production SQLite database has zero orphaned
   `order_items` rows, consistent with the Part 1 generation guarantee.

Run with `python3 test_edge_cases.py` (plain) or
`python3 -m pytest test_edge_cases.py -v` (if pytest is installed).
